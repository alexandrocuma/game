## What This Project Is

A single-player turn-based mobile hex exploration RPG built in Godot 4 + GDScript. A team of 2–4 heroes explores a fog-covered hex map tile by tile; each tile may trigger events (combat, gather, encounter, hazard). No backend server — all logic lives in the engine.

**Stack**: Godot 4 / GDScript / JSON save file (no database)
**Platforms**: iOS + Android
**Status**: Pre-implementation — design and documentation complete, no code written yet

## Core Principle — Read This First

**Content is data, not code.** Every tile, hero, event, enemy, upgrade, and theme is a JSON entry in `docs/content/`. The engine reads and merges these at startup. Systems operate on the merged data — they never reference content by name or hardcode behavior.

Rule: if you are writing a new hero, tile type, event, or enemy into a GDScript file, stop. Write a JSON entry instead.

→ Full principle: [`docs/game-design/GDD.md` — Design Principles](docs/game-design/GDD.md)

## Architecture at a Glance

→ Full detail: [`docs/technical/architecture.md`](docs/technical/architecture.md)

**Two autoloads** (registered in Godot Project Settings → Autoload):
- `GameState` — mutable runtime state, changes every turn
- `DataStore` — immutable content loaded once at startup from JSON catalogs + active theme overrides

**Turn state machine** (`turn_manager.gd`):
```
PLAYER_INPUT → ANIMATING → EVENT → WORLD_TICK → PLAYER_INPUT
```

**Hex grid**: use Godot's built-in `TileMapLayer` (tile shape = Hexagon). Never implement raw hex math — use `local_to_map()`, `map_to_local()`, `get_surrounding_cells()`. Custom helpers live in `hex_grid.gd`: `get_cells_in_range()` (BFS), `ring()`, `line()`, `find_path()` (A*), `path_cost()`.

## Implementation Playbooks

### Add a new tile type
1. Add a JSON entry to [`docs/content/tile-catalog.json`](docs/content/tile-catalog.json) — follow the schema in [`docs/technical/data-schemas.md`](docs/technical/data-schemas.md)
2. Add theme overrides to `themes/fantasy/tile_overrides.json` (including the `sprite` path to a 120×140 hex PNG)
3. Place the tile by adding a `{ "pos": [x, y], "tile": "<id>" }` entry to `docs/content/world-map.json` (the TileSet is built at runtime — no editor painting)
4. No script changes required

### Add a new event
1. Add a JSON entry to [`docs/content/event-catalog.json`](docs/content/event-catalog.json)
2. Add the event to the relevant event table (also in that file)
3. Add flavor text to `themes/fantasy/event_text.json`
4. If the event has a new `type` key not yet handled: add a handler branch in `event_manager.gd`
5. No other script changes required

→ Event type rules: [`docs/game-design/event-system.md`](docs/game-design/event-system.md)

### Add a new hero role
1. Add a JSON entry to [`docs/content/hero-catalog.json`](docs/content/hero-catalog.json)
2. Add theme overrides to `themes/fantasy/hero_overrides.json`
3. If the role has a new `passive` key: add the passive effect handler in the relevant system (`event_manager.gd` or `combat_resolver.gd`)
4. No other script changes required

→ Role passive keys: [`docs/game-design/hero-system.md`](docs/game-design/hero-system.md)

### Add a new enemy group
1. Add a JSON entry to [`docs/content/enemy-catalog.json`](docs/content/enemy-catalog.json)
2. Reference it by `id` in an event entry in the event catalog
3. Add theme overrides to `themes/fantasy/enemy_overrides.json`
4. No script changes required

→ Enemy schema: [`docs/technical/data-schemas.md`](docs/technical/data-schemas.md)

### Add a new theme
1. Create `themes/<id>/` folder
2. Write override files: `tile_overrides.json`, `hero_overrides.json`, `event_text.json`, `enemy_overrides.json`
3. Add `theme.json` metadata
4. Set active theme ID in game settings
5. Zero engine code changes

→ Full theme format: [`docs/game-design/theme-system.md`](docs/game-design/theme-system.md)

### Fix a game logic bug
- Data bug (wrong stat, wrong cost, wrong event weight) → fix the JSON in `docs/content/`
- Logic bug (wrong outcome, wrong state transition) → start at the relevant system script
- UI bug → start at the relevant UI script in `scripts/ui/`
- Always verify the JSON schema matches [`docs/technical/data-schemas.md`](docs/technical/data-schemas.md) before touching scripts

## v1 Hard Boundaries

Do not add the following in v1 — they are explicitly out of scope:

- Towns or NPC trade interactions
- Crafting system
- Online multiplayer or any network code
- Multiple themes (ship with fantasy only)
- Procedural map generation (hand-craft the first map)
- More than 2 hero roles in the active party
- Skill trees or ability branching beyond level perks

→ Full scope definition: [`docs/game-design/GDD.md` — v1 Scope](docs/game-design/GDD.md)

## Known Gotchas

- **Theme data is visual-only** — theme overrides cannot change stats, movement costs, or encounter chances. Only `label`, `name`, `sprite`, and text fields. See [`docs/game-design/theme-system.md`](docs/game-design/theme-system.md).
- **DataStore is read-only after startup** — never write to `DataStore` during gameplay. All runtime changes go to `GameState`.
- **Camp tile costs 0 movement** — it is the only tile with `movement_cost: 0`. Returning to camp never consumes a turn.
- **Event fires on first visit only** — re-entering a tile does not re-trigger its event (except combat tiles on retreat, which reset).
- **Rough terrain = 2 turns** — `movement_cost: 2` tiles consume the full turn even if the team has movement points remaining.
